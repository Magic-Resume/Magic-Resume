# AI 输入框重做 —— 设计简报（Design Brief）

> 产物类型：`/impeccable shape` 设计简报。上游语境：`.impeccable.md`、`docs/specs/ai-lab-living-canvas/design.md`、`docs/specs/light-theme/`。
> 目标组件：`apps/web/src/app/dashboard/edit/_components/ai/conversation/`。
>
> **修订说明**：本文 v1 记录的是「单层、无模式横幅、技能收进中性胶囊」的方案，那一版**已作废**——作者随后提供了一份 HTML 设计稿（双层外壳 + canvas 点阵模式条），方向整个改变。本文已按最终落地的实现重写，v1 内容不再保留，以免仓库里留一份与代码自相矛盾的 spec。

---

## 1. Feature Summary

AI 对话输入框（`Composer`）从「单层盒子 + 图标按钮」重做为**双层外壳 + 凹槽输入井 + 顶部点阵模式条**的结构，并新增三件此前没有的能力：与技能正交的**模式轴**、**语音听写**、面向云端免费用户的 **Pro 升级条**。面向的仍是在深色工作台里长时段打磨简历的求职者——这是他们与 Polaris 之间唯一的常驻入口。

## 2. Primary User Action

**把想法打出来并发出去。** 附件、模式、模型、语音、升级全是配角，不允许在视觉重量上盖过它。这条是所有尺寸取舍的裁决标准（见 §4 的比例说明）。

## 3. Design Direction

**概念：一台有状态的工作台。**

三层表面自外向内逐层变暗：外壳（最亮）→ 内层面板 → 凹槽输入井（最暗）。顶部一条 28–30px 的模式条常驻，用 canvas 点阵实时表达「AI 现在处于什么关系」。

> **一处不可照搬**：设计稿的页面底是中灰紫 `oklch(0.251)`，它的输入井 `oklch(0.134)` 比页底更暗；我们的桌面底是 `#0A0A0A`（0.145），照抄绝对值会让输入井沉进背景里。移植的是**相对关系**（逐层向内变暗、控件比卡面高约 5% 明度、无外框），整体抬到 desk 之上。

**保持不变的身份锚点**：sky `#38bdf8` 仍是唯一强调色；动效只用 transform / opacity，不弹跳；技能各自的 accent 色**退出输入框**（控件行里唯一有颜色的是模式胶囊——因为「AI 能不能动我的简历」是这一行唯一有后果的选择）。

## 4. Layout Strategy（含实测数值）

```
┌──────────────────────────────────────────────┐  ← 外壳 r=30 · p=4 · 无外框
│░░ ⣿ 共创模式已就绪 ░░░░░░                    │  ← 模式条 30px（canvas 点阵）
├──────────────────────────────────────────────┤
│                                              │  ← 凹槽输入井 r=13 13 22 22 · p=10
│  说说要改什么，输入 / 唤起技能                  │     文字区 min 66 / max 132
│                                              │
│  ⊕ 添加文件  ▣ 共创 ⌄  ◉ gpt-5.5 · 高 ⌄   🎤 ↑ │  ← 控件行 38px
└──────────────────────────────────────────────┘
   ↕ 10px
┌──────────────────────────────────────────────┐
│ 升级到 Pro。查看 Pro 权益        〔升级〕 ✕   │  ← 60px · sky 辉光 · 仅云端免费档
└──────────────────────────────────────────────┘
```

**尺寸的由来。** 设计稿是 848px 宽的独立展示件，控件 58px、正文 24px；我们的容器 768px 且上方是 14px 的聊天气泡，直接照搬会让输入框变成绝对主角。整体按 ×0.7 缩到面板节奏后再按实际观感收敛，最终：

| 项 | 值 | 说明 |
|---|---|---|
| 外壳圆角 / 内边距 | 30px / 4px | |
| 内层面板圆角 | 26px | **不可加 `overflow-hidden`**，见 §7 |
| 模式条 | 30px 高 | 自身 `overflow-hidden` + `rounded-t-[26px]` 负责裁剪 canvas |
| 输入井圆角 / 内边距 | 13 13 22 22 / 10px | 上角小、下角随面板，读作「井被塞在模式条下面」 |
| 文字区 | **min 66 / max 132px**，16px/1.5 | |
| 文字区 → 控件行 | 12px | |
| **控件行（全部同高）** | **38px** | 胶囊、模型选择器、麦克风、发送键一律 38 |
| 控件间距 | 10px | |

**文字区 66px 是这份简报最后一次修订的核心。** 控件 38px 固定，设计稿里「文字区 : 控件行」= 1.14；此前文字区是单行 24px，比例倒挂成 **0.63**——控件行比写字的地方还高 1.6 倍。用户反馈的「按钮大小有点怪」是这个倒挂的症状，不是按钮绝对尺寸的问题。把文字区抬到 66px 后比例变为 **1.74**，控件占外壳高度从 40% 降到 27%，按钮一个像素未动。

**控件行的三档视觉重量**：

| 档 | 表达 | 成员 | 为什么 |
|---|---|---|---|
| 有框胶囊 | 卡面 +5% 填充 + hairline | 添加文件、技能胶囊 | 「会打开点什么 / 会带进来一个东西」 |
| 有色胶囊 | 模式 accent 微染 | 模式选择器 | 这一行唯一有后果的选择 |
| 无框控件 | 无填充无描边，圆标 + 文字 | 模型 · 强度 | 它是**状态显示**，只是恰好可点 |
| 圆钮 | 38px 正圆 | 麦克风、发送 | 动词，无标签，靠形状识别 |

**窄面板**：输入井挂 `@container`；宽度 < 420px 时「添加文件」的文字标签让位，按钮**收成正圆**而不是留一颗只装了「+」的宽胶囊——那种形状怎么调尺寸都难看。

**浅色主题**：全部走 `neutral-*` / 语义 token，`globals.css` 已把 Tailwind neutral 整档重映射为暖纸，所以浅色自动跟上。唯一显式处理的是 Pro 辉光（`.light .composer-pro-glow` 大幅降透明）。

## 5. 模式轴（与技能正交）

技能回答「做什么事」，模式回答「AI 与你的简历是什么关系」。三档：

| 模式 | 语义 | 前端**确定性**闸门（非提示词） |
|---|---|---|
| **共创**（默认） | 可直接产出简历改动，落到实时画布待确认 | 即现状 |
| **规划** | 只给方案与建议，不动简历 | 丢弃 `resume_update` / `resume_patch` |
| **问答** | 纯咨询，连简历都不读 | 不发 `resumeId` + 自动拒绝 `read_resume` 审批 |

**为什么不需要后端改动**：后端的 `mode` 是与技能绑死的闭集（`create|optimize|analyze|fit|translate|interview|general`），塞不进新维度。但三档里最硬的约束前端本来就攥着——`resumeId` 发不发、审批裁决、事件消费与否。`AGENT_MODES[*].contract` 只作为一条 `role: 'system'` 消息随每轮发出，让模型的**表达**对齐；真正的保证在 `AiChatShell` 的闸门里。

**技能 × 模式不兼容时**：`isSkillAvailableInMode` 把跑不成的技能从 `/` 菜单里过滤掉。过滤结果本身解释了三个模式——共创六个技能全在，规划只剩只读的分析类，问答一个都没有（就是纯聊天）。不过滤的话，「问答」模式下点「简历分析」会拿不到 resumeId 直接跑失败，用户看到的是「坏了」而不是「这不该在这儿」。

模式持久化进 `useAiSessionStore.agentMode`：关掉面板再打开，「我设成了不许改简历」这件事必须还在。

## 6. Key States

| # | 状态 | 表现 |
|---|---|---|
| 1 | 空态 | 66px 空框，占位符贴顶；下方留白**不填东西**——留白本身就是「可以多写点」的邀请。发送键为描边幽灵圆。 |
| 2 | 有内容 | 发送键点亮 sky 实心（≤150ms，仅 color/opacity）。 |
| 3 | 技能选中 | 控件行多一颗中性技能胶囊（图标 + 名称 + ✕）；空退格弹掉。 |
| 4 | 引用片段 | 输入井上方一张引用卡。 |
| 5 | 运行中 | 发送键**原位**变停止键；输入框禁用（**不是**排队——见 §9）。 |
| 6 | 录音中 | 麦克风点亮 sky + 脉冲；模式条文案换成「正在听… + 实时识别文字」，复用既有状态带而非另造 UI。 |
| 7 | 语音不可用 | 浏览器不支持 / 权限被拒 → **麦克风不渲染**。点了没反应的假按钮比没有更糟。 |
| 8 | 文本增长 | 66 → 132px 后内部滚动，控件行不被顶走。 |
| 9 | Pro 横幅 | 仅 `isCloudMode` 且当前是免费档（`priceCents === 0 \|\| isDefault`）。OSS 自部署版 `currentPlan === null` → 整条不渲染。关闭后隔 7 天再现（localStorage 时间戳）。 |
| 10 | 浅色主题 | 以上全部镜像。 |

## 7. 实现红线

- **内层面板不可加 `overflow-hidden`**。模式菜单与模型菜单都向上展开，会被裁掉（此坑踩过两次：旧版为模式横幅加的、新版为裁 canvas 加的）。裁剪只加在模式条自身。
- **SVG 标记不进 JSX**（仓库 house rule）。品牌标一律 `public/providers/{id}.svg`，唯一渲染处是 `components/llm/ProviderMark.tsx`，设置页与 AI Lab 共用同一批文件。
- **不写死 hex**，一律 `neutral-*` / 语义 token，否则浅色主题当场裂开。
- **IME 组合态判断**（`isComposing` / `keyCode === 229`）原样保留：中文用回车选候选词，丢了会导致打字打到一半就把消息发出去。
- **自增高的 FLIP 逻辑**（`prev` 回填 + `offsetHeight` 强制回流）原样保留，它是高度过渡不跳变的原因。
- **埋点属性** `data-magic-ai-skill-${id}` 原样保留。
- `ModeDotField` 的 rAF 常驻是选定方案，但 `document.hidden` 时必须停。
- 动效仅 `transform` / `opacity`，尊重 `prefers-reduced-motion`。

## 9. Open Questions

1. **运行中是否允许继续打字**。当前禁用输入框。改成可打字后回车会**顶替**正在跑的那次运行（`consumeStream` 会 abort 上一次），而不是排队——真做排队需要另加缓冲与续发逻辑，属于行为改动。留作独立议题。
2. **麦克风与「模拟面试」技能的图标撞车**：面试技能的图标也是麦克风。同一界面里两个麦克风隐喻指向不同东西，可能造成误解。
3. **对话态的垂直预算**：176px 的输入框在对话态会从聊天记录那边吃掉可观空间。当前欢迎态与对话态同高，是否需要对话态收一档，待实际使用后判断。
4. **聚合器服务商的模型目录**：OpenRouter / Groq / Together / Fireworks / 硅基流动 / 阶跃星辰 的 `models` 为空数组（UI 退回自由填）。若将来要给它们预置常用模型，需要一条能定期刷新的来源，而不是硬编码。
