# 资产库 · 设计简报

> 状态：Draft，待评审。后端已完成（`GET /api/workspace/artifacts`），本文只定 UX / UI，不含代码。
> 设计上下文来源：`.impeccable.md`。

## 1. 功能概述

Agent 在对话里产出的岗位调研、公司画像、版式复刻和求职信，此前全部沉在库里没有消费端——用户看不见，下次要用只能重跑一遍。资产库把这些产出变成一个**能翻回来、能直接接着用**的地方。

面向正在为目标岗位打磨简历的求职者。账号级：一个人的调研跨所有简历共享，简历是筛选面不是隔离墙（理由见 `~/.claude/plans/unified-scribbling-seal.md`）。

## 2. 主行动

**找到上次那份调研，把它接着用起来。**

不是「管理文件」，不是「审计 agent」。用户来这里是因为他现在要写字节的求职信，而三天前已经查过字节的 JD——他要的是那份内容，以及一条把它送回工作流的路。

这一条决定了下面每个取舍。

## 3. 设计方向

沿用深色工作台（`#0A0A0A`）+ sky 点缀、少 border。动效仅 transform / opacity，切换预览用**淡入 + 2px 位移**，不做横向滑动——它读作「翻页」，而这里是同一块地方换内容。

**与「就地而非另开」的张力，明确解掉**：这条原则针对的是**改动**（改简历要标在简历上，不另开 diff）。资产库不是改动，是**归档**，它本来就该有一个能回去的地址。两个入口各司其职：

- **AI Lab 左抽屉**：就地。列本简历最近几条，点开在**右舞台**（`ArtifactCanvas`）渲染，不离开对话
- **dashboard 侧栏 → `/dashboard/assets`**：全量的归档地址，跨简历

**它不是一个静态柜子，是一块会褪色的白板。** 调研 7 天、logo 30 天、交接 1 天后自动过期。这个事实必须在界面上说出来——用户回来找上周的调研却发现空了，会认为系统把东西弄丢了，而那正是这几轮一直在修的「界面在说谎」。

## 4. 版面策略

**Master-detail 两栏，预览占主。**

```
┌──────────────────┬───────────────────────────────────────┐
│ 资产库            │                                       │
│ ┌──────────────┐ │  岗位调研 · 字节跳动 前端开发           │
│ │ 🔍 搜索       │ │  前端简历 · 2 天前 · v3                │
│ └──────────────┘ │  ● 5 天后消失            [📌 留住]      │
│ 全部 7  调研 3    │  ─────────────────────────────────────│
│ 公司 2  版式 1    │                                       │
│ 求职信 1          │  ## 岗位要求                           │
│                  │  - 三年以上 React 工程经验              │
│ ● 岗位调研        │  - 有大型项目性能优化经验               │
│   字节 前端       │                                       │
│   2 天前 · 5 天后 │  ## 技术栈                             │
│ ─────────────    │  …                                    │
│ ○ 公司画像        │                                       │
│   阿里            │                                       │
│   4 天前          │  ─────────────────────────────────────│
│ ─────────────    │  [ 拿它优化简历 ]  [复制]  [归档]       │
│ ○ 版式复刻        │                                       │
└──────────────────┴───────────────────────────────────────┘
     ~300px                      剩余全部
```

**为什么不是表格**：表格是用来横向比较的（投递面板：公司 / 岗位 / 状态 / 日期，你扫着比）。资产只有一个有意义的列——标题；用户不比较，他找到一条然后**读**。把正文挤成一行摘要，正好挤掉了主行动。

**层级**：预览区的标题 → 元信息 → 正文 → 动作条，四段。列表项是次要的，用**中性色 + 选中态 sky 左边线**，不给每项加卡片外壳（少 border）。

**筛选 chips 抄投递面板那一排**：同样的高度、同样的选中态、计数是**纯文字不加底色**（照搬 `bg-field` 那次的教训）。

**响应式**：窄屏（< 900px）退成单栏——列表全宽，点一条**推入**预览、左上角返回。不用抽屉：抽屉盖在列表上，而这里用户是要专心读内容的。

## 5. 关键状态

| 状态 | 用户需要看到 / 感受到 |
|---|---|
| **默认** | 列表按更新时间倒序，第一条**自动选中**并渲染预览——右边是空的会让人以为要先点一下才有东西 |
| **从没用过 AI（真空）** | 不是「暂无数据」。这是小蓝宠该出场的地方：说清这里会攒什么（「你让我查过的岗位、公司、版式都会存在这儿」）+ 一条去 AI Lab 的路。**这是唯一允许展现性格的文案位** |
| **筛完空了** | 和真空**必须分开**。「这个筛选下没有资产」+ 一键清筛选。用同一句「还没有资产」会让用户以为东西没了 |
| **加载中** | 列表画骨架行（形状先摆出来），不转圈。预览区留白不放 spinner——它 200ms 内就到 |
| **预览加载中** | 内容是**第二个请求**（`GET /artifacts/:id`），列表项已选中但正文未到：标题和元信息先出（列表里已有），正文位置画骨架 |
| **即将过期（< 48h）** | 元信息行的圆点转 `--orange`，文案从「5 天后消失」变「明天消失」/「今天到期」。**不用红**——红在这套语言里是简历删除线，挪用会串味 |
| **已留住** | 圆点消失，改一枚 📌 + 「已留住」。是**状态**不是按钮，别让人误以为还能再点一次 |
| **预览失败** | 三种真实错误分开说：过期（410）「这份已经过期了」、归档（409）「已归档的内容不再保留」、不存在（404）。**不要**统一成「加载失败」——前两种是可解释的，用户需要知道是自己没留住 |
| **归档后** | 从当前筛选里移走 + 一条可撤销的提示。归档不是删除，但**归档后正文读不出来**（后端 `read()` 对非 READY 抛 409）——所以按钮文案必须是「归档」，绝不能写成「隐藏」 |
| **接近 500 上限** | 后端硬上限 `MAX_ACTIVE_ARTIFACTS = 500`。到 450 时在列表顶部给一条低调提示，别等发布失败了才说 |

## 6. 交互模型

- **点列表项** → 右侧换内容。选中态是**左边 2px sky 线 + 底色微亮**，不用整块蓝底
- **搜索**：只搜标题（后端 `q` 就是 title contains）。**必须在占位符里说清**「搜标题」，否则用户搜正文里的词搜不到会以为坏了
- **「拿它优化简历」** —— 主行动的出口。跳到该资产来源简历的 AI Lab，并把这条资产**预填进输入框**（一句引用 + 资产 id），用户按回车即开始。不自动发送：AI 是合作者不是推土机，最后一下得他按
- **「留住」** → 清掉 `expiresAt`。就地变状态，不弹确认——这是一个只增不减的安全动作，确认框是噪音
- **「归档」** → 需要确认，因为正文从此读不出来。确认走行内二次点击（「确定归档？」），不弹模态
- **「复制」** → 复制正文 markdown，按钮就地变「已复制」
- **AI Lab 左抽屉里** 点一条 → 右舞台渲染，**不跳转**

## 7. 文案需求

全部走 i18n（zh 为主、en 对齐），键落在 `aiLab.assets.*` / `sidebar.assets`。

| 位置 | zh |
|---|---|
| 侧栏 | 资产库 |
| 搜索占位 | 搜索标题 |
| 类型 chips | 全部 / 岗位调研 / 公司画像 / 版式复刻 / 求职信 |
| 元信息 | `{{简历名}} · {{相对时间}} · v{{版本}}` |
| 过期（>48h） | {{n}} 天后消失 |
| 过期（<48h） | 明天消失 / 今天到期 |
| 已留住 | 已留住 |
| 真空标题 | 这里还是空的 |
| 真空正文 | 你让我查过的岗位、公司、版式都会存在这儿，随时能翻回来接着用。 |
| 真空动作 | 去 AI Lab 看看 |
| 筛空 | 这个筛选下没有资产 |
| 主动作 | 拿它优化简历 |
| 归档确认 | 确定归档？归档后正文不再保留 |

**动态范围**：标题由 agent 写，长度不可控 → 列表项两行截断、预览区标题不截断但要能换行。简历名同理。类型 chips 是固定四项，中英文宽度差异大，chips 行要能横向滚动（同投递面板）。

## 9. 待解问题

1. **「留住」需要后端新增接口**——清除 `expiresAt`。现有 controller 没有 PATCH，要加一个（小改动，但不做的话第 2 个设计决定就落不了地）。
2. **「拿它优化简历」怎么把资产传给 AI Lab**：预填输入框需要一个引用格式，且 agent 侧要能凭 id 读到内容（`read_artifact` 工具已存在，但它按 per-resume 路径读，跨简历引用时要确认能不能拿到）。
3. **归档的资产在列表里还出不出现**：后端 `list` 返回 READY + ARCHIVED 两种。倾向默认筛掉、给一个「已归档」筛选面——但归档后正文读不出来，那个筛选面点进去只能看元信息，价值存疑。**建议实现时先默认筛掉、不给筛选面**，等有人问再说。
4. 版式复刻（`TEMPLATE`）和 logo 集的预览形态没定——前者可能是图片或 DSL JSON。首版按 `mimeType` 分派到 `Markdown` / `CodeBlock` / `<img>`，认不出的类型给一条「这类内容暂不支持预览」而不是渲染乱码。
