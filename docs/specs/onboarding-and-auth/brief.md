# 登录与首次引导 · 设计简报

> 状态：Draft，待评审。**只定 UX / UI，不含代码。**
> 设计上下文来源：`.impeccable.md`。参考对象：LobeHub 的登录页与首次引导。

## 1. 概述

两个界面，同一个时刻：**一个人决定要不要用这个产品的那五分钟。**

- **登录页** —— 现在是 Clerk 默认观感，且**没有服务条款门禁**
- **首次引导** —— 已有一版全屏四步，但它是一张摊开的表单：内容漂在巨大的空场里、没有容器、没有焦点、没有角色，读起来像后台配置页而不是一次见面

目标是把这两屏做到**用户会截图发给朋友**的程度。

## 2. 主行动

| 界面 | 用户要做的唯一一件事 |
|---|---|
| 登录 | **用最少的动作进去**——三个 OAuth 摆在最显眼处，邮箱是退路不是主路 |
| 引导 | **说清他在找什么工作**——尤其是第四步「现在最难的是哪一步」 |

## 3. 设计方向

### 从「摊开」改成「聚拢」

当前引导最大的问题是**没有容器**：1/4 的进度点缩在左上角，标题在正中偏上，chips 铺到屏幕两端，按钮沉到右下角——四组元素分居四方，眼睛无处落脚。

改成 LobeHub 那种**居中卡片**：一块 ~760px 宽、圆角 16px、hairline 描边的面板浮在深色底上，所有内容收进去。空场从「空洞」变成「留白」——同样的黑，一个是没画完，一个是画好了。

### 角色是主角，不是装饰

`public/marks/` 里已经有六种姿态的 Polaris 小蓝宠。LobeHub 用 3D 角色串起每一步，我们有等价物，而且是自己的品牌资产（`.impeccable.md`：呆萌外表·靠谱内核）。

**每一步换一个姿态**，角色随问题推进改变神情：

| 步 | 资产 | 神情 |
|---|---|---|
| 1 · 方向 | `polaris-pet-sit.svg` | 坐下来听 |
| 2 · 阶段 | `polaris-pet-thinking.svg` | 歪头想 |
| 3 · 底子 | `polaris-pet-typing.svg` | 记下来 |
| 4 · 卡点 | `polaris-pet-excited.svg` | 懂了 |
| 生成中 | `polaris-star.svg`（自带关键帧） | 星光转起来 |

这一下就把「填表」变成「有个小家伙在听你说」——而那正是这个产品的情绪目标（让用户有被理解感）。

**角色区不是一张贴图**：卡片顶部一条 ~180px 高的横幅，角色居中偏左，背后是一层随步骤换色相的柔光（sky → 青 → 紫 → 暖），只用 `opacity` / `transform` 推动。切步时角色**淡出淡入 + 轻微上浮**，不做位移横飞。

### 惊艳从哪来

不靠更多装饰，靠三件事：

1. **一块共用的高亮在选项间滑过去**（已实现的 `layoutId` 手法）——它读作「同一个焦点在走」，而不是十个各自亮灭的灯
2. **角色随你的回答换表情**——反馈来自一个"活物"，不是一个进度条
3. **最后那一屏画像逐字写出来**——用户看着自己的画像被生成，这是整个流程唯一的"魔法时刻"

### 引导（每一步）

```
│  ╭────────────────────────────────────────────────╮  │
│  │        （柔光背景）    🧍 Polaris                │  │  ← 180px 横幅
│  ╰────────────────────────────────────────────────╯  │
│                                                       │
│   你在找什么工作？                                     │  ← 24px 粗体
│   先说个大方向，之后随时能改                            │  ← 13px 次色
│                                                       │
│   目标岗位                                             │
│   ( 前端 ) ( 后端 ) ( 全栈 ) ( 算法 ) …  ( + 自己填 )   │
│                                                       │
│   行业方向                                             │
│   ( 互联网 ) ( 电商 ) ( 金融 ) …                       │
│                                                       │
│  ────────────────────────────────────────────────────│  ← hairline
│  💡 之后可以随时修改              ●─●─○─○      [ 继续 ]│
└──────────────────────────────────────────────────────┘

```

关键改动，逐条对着现在这版：

| 现在 | 改成 |
|---|---|
| 内容铺满整屏 | 收进 ~760px 居中卡片 |
| 进度点在左上角，远离一切 | 挪进卡片**底栏**，紧挨「继续」——它描述的是这颗按钮的进度 |
| 「1/4」文字 + 圆点重复表达 | 只留连接线圆点，去掉数字 |
| 「跳过」和「下一步」并排、等重 | 「跳过」移到**卡片外下方**，弱化但仍可点（脚手架不是栅栏，但也不该和主行动抢） |
| 关闭 X 在右上角孤零零 | 去掉——「跳过」已经是退出，两个出口是冗余 |
| chips 无边框、静息时像纯文本 | 静息给 hairline 描边，选中才上共用高亮 |
| 无副标题 | 标题下一行说清这一步问的是什么范围 |

### 登录

抄 LobeHub 的骨架，换我们的令牌：

```
   ✦ Magic Resume
                     登录或注册 Magic Resume
        ┌───────────────────────────────────┐  ┌上次使用┐
        │  G     使用 Google 登录            │  └───────┘
        ├───────────────────────────────────┤
        │  ⌥     使用 GitHub 登录            │
        └───────────────────────────────────┘
                    ── 或继续使用 ──
        ┌───────────────────────────────────┐
        │  ✉   邮箱地址                      │
        └───────────────────────────────────┘
        ☑ 我已阅读并同意 服务条款 与 隐私政策
        ┌───────────────────────────────────┐
        │              下一步                │  ← 实心，浅底深字
        └───────────────────────────────────┘

  简体中文 ⌄  ☾                     服务条款 · 隐私政策
```

- 列宽 ~380px，比引导卡窄——登录是**单列决策**，越窄越快
- OAuth 按钮全宽、图标居左、文字居中（这是 LobeHub 那份看起来稳的原因：图标不参与居中计算）
- 主按钮**浅底深字**，是整屏唯一的高对比块

## 5. 关键状态

| 状态 | 用户要看到 / 感受到 |
|---|---|
| **引导 · 未答** | 「继续」暗着但**可点**——点了等于跳过这一步。禁用会让人以为卡住了 |
| **引导 · 已答** | 「继续」亮起，角色轻微反应一下（缩放 1.0→1.03→1.0） |
| **引导 · 生成中** | 角色换成会动的星，画像 markdown **逐字写出**。**不显示进度条**——它写多久取决于模型，假进度条会撒谎 |
| **引导 · 生成失败** | **不拦人**。照常进 dashboard，不弹错误——画像没生成的代价是 AI 少知道一点，不是流程走不下去 |
| **引导 · 跳过整张** | 直接进 dashboard，不生成画像、不留痕迹。下次进来再问一次 |
| **登录 · 未勾条款** | 主按钮和 OAuth 都**仍可点**——点了弹确认框（见下），而不是把按钮灰掉。灰按钮不解释原因 |
| **登录 · 条款确认框** | 标题「确认服务条款与隐私政策」+ 正文带链接 + 取消 / 同意并继续。「同意并继续」**同时勾上复选框并继续原动作** |
| **登录 · 上次使用** | 用过的 provider 右上挂一枚「上次使用」小徽标（本地记录，不是账号数据） |
| **登录 · 错误** | 错误贴在触发它的控件下方，不弹 toast |
| **两者 · 窄屏** | 卡片降为全宽 + 上下留白收紧；角色横幅高度减半 |

## 6. 交互模型

- **选项**：Radix `RadioGroup` / `ToggleGroup` —— 一组 chips 只占一个 Tab 停点、左右键在组内移动。手写按钮做不到这层
- **「自己填」**：点开变输入框，回车提交、Esc **放弃**（写一半反悔不该被留下半个词）
- **换步**：出去的向上淡出、进来的向下淡入，错峰 60ms；角色同步换姿态
- **底栏进度**：连接线 `scaleX` 推进，圆点当前步放大 1.5×
- **条款确认框**：Radix `Dialog`，「同意并继续」勾上复选框**并直接执行**用户原本点的那个动作——让他再点一次是惩罚
- **降级**：`prefers-reduced-motion` 下全部降为纯淡入，角色不做浮动

## 7. 文案

引导每一步补一句**副标题**（现在没有），说清这一步的范围：

| 步 | 标题 | 副标题 |
|---|---|---|
| 1 | 你在找什么工作？ | 先说个大方向，之后随时能改 |
| 2 | 现在处在哪个阶段？ | 应届和转行需要的建议不一样 |
| 3 | 你的主要技术栈是？ | 决定简历里哪些经历值得放大 |
| 4 | 现在最难的是哪一步？ | 这条决定我先帮你做什么 |

底栏提示：`💡 之后可以随时修改`（抄 LobeHub，因为它准确——画像在设置里能改）。

登录：`登录或注册 Magic Resume` / `或继续使用` / `我已阅读并同意 服务条款 与 隐私政策` / `还没有账号？创建账号`。

全部走 i18n，zh/en 都要。

## 9. 约束与待解

1. **登录页只重做视觉，逻辑一行不动。** CLAUDE.md 有三条写明的例外在保护 `SignInCard`（按 `supportedFirstFactors` 选下一步、`session_exists` 当已登录、`redirect_url` 同源校验）——那三条都是真事故换来的，动它们等于把修好的 bug 放回来。
2. **条款同意要落库**，见下面第 10 节——那里有个时序问题必须按那个顺序做。
3. **角色横幅的柔光换色相**要确认在浅色主题下不发灰——`.impeccable.md` 说浅色靠「清晰 hairline + 落地暖阴影」，深色那套发光在浅色下会糊。
4. Polaris 六个 SVG 的**画布尺寸和视觉重心是否一致**未验证。不一致的话切步时角色会在横幅里跳位，需要先统一 viewBox 或给每个姿态单独的定位偏移。

## 10. 条款同意的落库

### 10a. 一个必须先解决的时序问题

**勾选发生在登录之前，那时还没有可以写的用户行。**

Clerk 负责鉴权，本地 `users` 行是**登录后**由 `ClerkAuthGuard` 的 JIT `provisionLocalUser` 补上的（此前正是因为没有这一步，发不了积分）。所以「勾了框 → 立刻写库」这条路走不通：没有 userId，没有 token，写不进去。

正确顺序：

```
① 用户勾选（或在确认框点「同意并继续」）
     ↓  只落在内存 + sessionStorage（撑过 OAuth 跳转）
② 走 Clerk 登录 → 回跳 → JIT 建出 users 行
     ↓
③ 首次带鉴权的加载时，前端把待写的同意补上去
     POST /api/users/me/terms { version }
     ↓
④ sessionStorage 清掉
```

**用 `sessionStorage` 而不是内存**：OAuth 会整页跳出去再跳回来，内存里的勾选状态到不了第 ③ 步。也不用 `localStorage`——同意意向不该跨会话留存。

### 10b. 数据

```prisma
model User {
  /// 同意服务条款的时刻。空 = 从没同意过（存量用户即是）。
  termsAcceptedAt DateTime?
  /// 同意的是哪一版。条款改版后与当前版本不符 = 要重新征求同意，
  /// **只存时间戳是不够的**：那样改了条款也无法区分谁同意的是旧版。
  termsVersion    String?
}
```

迁移按仓库规矩：`migrate diff` 生成后**手工裁剪**（生成脚本会顺手 DROP 掉 pgvector 的 HNSW 索引、改 `app_config` 默认值、重命名 keeper 索引——那些是既有漂移），再跑 `node scripts/check-migrations.mjs` 过闸。**禁 `migrate dev` / `reset`**。

当前版本号写成一个常量（如 `TERMS_VERSION = '2026-08-26'`），前后端共用一处，别两边各写各的。

### 10c. 端点

`POST /api/users/me/terms`（platform-api 的 users 模块，已有 `@Controller('users')`）：

- 只接受 `{ version }`，**时间戳由服务端打**——`acceptedAt` 让客户端传等于让它自己编同意时间
- 校验 `version` 必须等于服务端当前版本，不认历史版本或未来版本
- 幂等：重复提交同一版本就更新时间戳，不报错

### 10d. 存量用户与改版

`termsAcceptedAt` 为空、或 `termsVersion` 不等于当前版本的**已登录**用户，在进入 `/dashboard` 时弹一次条款确认框（复用登录页那个 Dialog，不另做一套）。

**只有「同意」一个出口**，没有取消——不同意就用不了，这是事实，给一个假的「取消」等于让他以为还有别的选择。但要给「退出登录」，那才是真正的另一条路。

这一条同时覆盖两种人：老用户（从没记录过）和条款改版后的所有人。

### 10e. 状态补充（接第 5 节）

| 状态 | 表现 |
|---|---|
| 勾了但登录失败 | `sessionStorage` 里的意向**保留**——他确实同意过，重试登录时不该再勾一遍 |
| 补写 `POST /terms` 失败 | **不拦人**，静默重试一次；仍失败就留到下次带鉴权的加载。拿同意记录去挡用户进门是本末倒置 |
| 存量用户看到重新确认 | 文案要说清「条款有更新」，而不是让他以为自己从没同意过 |

## 11. 画像在哪看、怎么改

参照 ChatGPT 的「记忆摘要」。下面几条是从那个界面里挑出来该学的，和一条**刻意不学**的。

### 11a. 两层结构，一个页面

ChatGPT 的设置里是「记忆摘要」（一份文档）+「已保存的记忆」（一条条事实）。我们已经有下面那层——`dashboard/settings/_components/MemorySection.tsx` 的开关加条目列表。求职画像补的正是上面那层。

所以它**落在同一个设置页**，作为 `MemorySection` 上方的一块，而不是新开一页（推翻本轮计划 §4c 的「加一页」）。两者相邻而分栏，本身就把差别说清楚了：上面这份是用户亲口说的、一直生效；下面那些是 AI 推断的、会过时、会衰减。

### 11b. 面板

设置页那一行只放一句摘要 + 「管理」，点开才是面板：

- 标题旁一行 **「刚刚更新 / N 天前更新」**。画像每轮都注进 prompt，「它有多新」是用户唯一能据以判断「AI 现在到底懂不懂我」的线索
- 正文按固定小节渲染 markdown，复用 `conversation/Markdown.tsx`，不另写一套渲染
- 底部一个输入框（见 11c）
- 「…」菜单里放重新生成 / 删除——低频且不可逆，不该和日常动作摆在同一层

### 11c. 用一句话改，不手改 markdown

这是那个界面里最值钱的一处，也是与原计划出入最大的一处。

原计划写的是「显示 markdown、可编辑」——即一个 textarea。但没有人想编辑「第 2 小节第 3 行」；他脑子里的原话是**「我不去杭州了」**。让他说这句、由模型去改文档，才是这个交互该有的形状。

**但改动要先给 diff 再落**——这一条与 ChatGPT 不同，它是直接改完告诉你：

1. 输入一句话 → 服务端合成候选正文，**不落库**
2. 前端展示改了哪几行（红删绿增，复用简历修订那套颜色）
3. 「应用 / 放弃」；应用后 `revision + 1`

依据是设计原则 ③（改动先提案、可拒绝、有理由）。这里比别处更该守：画像每一轮都注进 prompt，写坏了污染的是此后**所有**对话，而不是一次回答。

对应的端点在原 §三 上加一个，`PUT` 保持「直接落库」不变：

- `PATCH /api/job-profile` —— 收 `{ instruction }`，回 `{ content }` 候选正文，**不写库**
- `PUT /api/job-profile` —— 收 `{ content }`，落库并 `revision + 1`

diff 那一步因此不需要额外的表或草稿态。

**这个框只改画像，不做问答。** ChatGPT 那个框兼了「提问或更新」，但我们旁边就是 Polaris，再放一个会话入口是两个对话框打架。占位符写「说一句话改它」，不写「提问」。

### 11d. 开关

与 `MemorySection` 同一语义：**停用 ≠ 删除**，两件事分开。停用后画像仍在库里、仍看得见，只是不再注进每轮 prompt。
